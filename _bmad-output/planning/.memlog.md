- (decision) Product is a Go scheduling sidecar for a separate main application; the caller is that application, not an end user.
- (decision) v1 capabilities are exactly the README list: list/create/edit/cancel events, conflict check, list/create/delete contacts, add/update availability, record logs.
- (decision) NFRs from README: low-latency event lookup, consistency of event and availability, horizontal scale, no UI and no auth, peak about 120 req/s.
- (decision) Transport, MySQL, and Redis are technical-how and belong in addendum.md, not as product behavior in the PRD body.
- (assumption) An event has a time range; otherwise conflict and availability cannot be defined. README does not state fields.
- (assumption) Edit and cancel are two operations. Cancel keeps the event as a record and removes it from conflict consideration.
- (assumption) A contact is the party whose time is scheduled. Availability belongs to a contact.
- (question) What latency bound counts as low-latency event lookup, and may a cache serve a stale event or availability row?
- (event) Fast path draft from README.md. No initiative set. User forbade source edits and AGENTS.md. Status remains draft.
- (decision) Low-latency event lookup means p99 under 50 ms. User confirmed.
- (decision) A read must match the last successful write. Cache must not return an event or availability older than that write. User confirmed.
- (decision) Event fields are title, capacity, date, start time, and end time. User confirmed. Contact link on an event is not confirmed.
- (decision) A contact is a person with name, email, and phone. User confirmed. Whether an event names a contact is still open.
- (decision) Every event has one contact as organizer. Additional contacts may be associated as participants. User confirmed. Who among them a conflict checks is still open.
- (decision) No gap is required between events. A start time equal to another event's end time is not a conflict. User confirmed.
- (decision) Conflict counts both the organizer and the participants. User confirmed.
- (decision) A contact delete sets inactive status and does not remove the row or rewrite events. Delete is rejected while the contact is organizer or participant on an event whose start time is still in the future. User confirmed. Whether lists include inactive contacts is open.
- (decision) Availability is a block of time. Smallest unit is 15 minutes. Example 3:00 PM-10:00 PM. User confirmed. Whether the block has a date, and whether update replaces or merges, remain open.
- (decision) An availability block belongs to a date. User confirmed. Whether update replaces or merges remains open.
